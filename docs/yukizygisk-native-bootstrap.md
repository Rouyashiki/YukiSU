# Native bootstrap through the libc host

Native ZN uses SYSTEM loading through `libyloader32.so` or `libyloader64.so`.
The loader is a temporary Bionic object; the Core is a private anonymous image
containing its own SDK runtime. Ordinary Zygisk retains its PRIVATE-first policy.
The native path ignores the ordinary private-loader configuration.

This is an explicit libc host policy, not discovery of an arbitrary module's
intended namespace. There are no process allowlists, namespace-name assumptions,
symbol-hit searches across namespaces, or namespace retries.

## First-stage identity

The kernel stages descriptors, a small startup stub and a separate freestanding
resolver, then replaces native AT_ENTRY. The resolver runs after Bionic has
initialized the executable. ARM32 enters the generated stub in ARM mode and
restores the original entry's Thumb bit.

`userspace/zygisk/inject/native_resolver.c` validates AT_BASE against readable
mapped ELF segments and resolves these exact linker exports:

- `__loader_android_dlopen_ext` (four arguments, including caller)
- `__loader_dlsym`, `__loader_dladdr`, `__loader_dlclose`
- `__loader_dl_iterate_phdr`, `__loader_dlerror`

The real PHDR enumerator holds Bionic's recursive linker lock across a second
complete census, libc pinning, loader opening and native binding. Candidates
must have a valid ABI/ELF, SONAME `libc.so`, a defined executable `getpid`, and
matching PHDR and `dladdr` ownership. Exactly one candidate is accepted.
`RTLD_NOLOAD` pins `libc.so` in that candidate's own scope; a concrete-handle
lookup must resolve to the same `getpid` address. This is one operation with
identity validation, not a path/namespace retry.

The original loader is opened from its staged fd using USE_LIBRARY_FD and
FORCE_LOAD, with that verified libc address as caller. Any resident loader
SONAME is rejected before this operation. Its new bind/entry exports must
belong to the same returned image. DT_NEEDED and a concrete lookup verify an
independent dependency on the selected libc before releasing the temporary pin.
Cleanup failure preserves the owned references in the launch descriptor.

The resolver contains no imports, runtime initializers, TLS or dynamic
relocations. `generate.py --write` produces both checked-in blob headers;
`generate.py` rebuilds and compares them. Windows/Linux builds and the payload
and LKM workflows enforce this check with NDK 30/API31. Native integration tests
execute the generated bytes, including the failure paths and register probes.

The large resolver mapping is removed before Core entry. The small launch page
and descriptor remain, as with the previous AT_ENTRY trampoline. x16 on ARM64
and r12 on ARM32 are continuation branch scratch registers. Other saved general
registers, SIMD state, SP, flags and ARM32 Thumb state are restored.

## Bind, service and handoff

The additive same-process SDK extension is version 1:

1. `yuki_bootstrap_bind_native_v1` receives the exact original loader reference,
   copied libc/linker origin, PID, generation and an external completion record.
   Successful binding consumes one reference; refusal consumes none.
2. `yuki_bootstrap_native_v1(int, int)` privately loads Core and validates its
   required native capability before executing Core constructors.
3. `zygisk_bootstrap_bind_native_v1` copies a temporary synchronous open service
   into Core. Core adoption then accepts the original loader reference.
4. Core initializes its runtime, API and HyOS environment. Early and initial late
   module loading selects the existing SDK SYSTEM slot. Its Core-owned
   HostServices open callback borrows the fd and delegates to the temporary
   service. `android_dlopen_ext` executes at a non-tail call site inside loader.
5. Core queries `zn_module`, checks versions, performs registration and retains
   the SDK owner/generation handle. No second open or new handle-adoption API is
   used. Native modules retain Bionic soinfo, TLS and PHDR registration, and their
   own libdl calls retain their real Bionic identity.
6. Core closes admission, drains calls and clears loader callback/context
   pointers before ready. Later Core module-open attempts fail explicitly.
   Module-originated Bionic opens continue independently.
7. Dependencies transfer only after acceptance. Finish succeeds before the
   mandatory tail call into Core's finalizer. That finalizer releases precisely
   the initial loader reference, with a surviving external return chain.

The service states are Unbound, Open, Draining and Revoked. PID and bootstrap
generation bind the service to one attempt. A copied origin is descriptive;
the live loader dependency and subsequent Core dependency references maintain
libc lifetime. No pointer into the temporary resolver is retained.

The completion record lives in the small launch descriptor and is borrowed
only through native entry. RETAINED keeps ambiguous ownership; ADOPTED means
Core owns the reference; RETURNED is allowed only after complete pre-execution
rollback. In the last case the external launch stub closes the original loader
reference after entry returns. A loader never closes its own active return
chain. Reentry or a fork child cannot commit a second handoff.

## Lifetime and rejection

SYSTEM failures never retry PRIVATE or another namespace. Module constructors
and native entry each run at most once per successfully loaded instance.
Early/late deduplication, companion binding and HyOS registration remain Core
responsibilities. Failed registration and failed close retain their full SDK
outcomes and ownership records. Core stays resident while modules use its API,
hooks, companion state, HyOS callbacks or synchronization thread. The existing
drain, destructor, dependency release and external continuation retire an idle
Core.

Explicit Core/Zygote/HyOS fork paths retain SDK/YukiPLT coordination. Fork during
the temporary window cannot reuse the inherited service or finish handoff in
the child. Native modules themselves use Bionic fork/libdl. Child libdl calls
after a multithreaded fork require system-loader activity to have been quiesced;
the test runtime also deadlocks in a standalone Bionic-only reproducer when a
different thread holds the linker mutex at fork. This change does not promise
async-signal-safe libdl. Raw native forks do not enter Core's YukiPLT dispatcher;
Core hook operations from an uncoordinated child retain their existing refusal.

Rejected cases include absent/ambiguous libc, invalid or unreadable ELF,
unsupported exact linker exports, resident loader, identity mismatch, obsolete
native capabilities, stale PID/generation, revoked window and uncertain cleanup.
The kernel report fd is bound to its creating process and bootstrap generation;
failure records status/stage, marks the attempt failed and restores temporary
load policy. Module-open diagnostics include module, backend, libc origin,
generation and the copied Bionic error.

## Paired deployment and verification

The LKM advertises `YZ_RUNTIME_CAP_NATIVE_LIBC_BOOTSTRAP_V1`. The new daemon
rejects kernels without it. The on-disk early snapshot is version **3**, which
requires this native capability; its struct layout is unchanged. The old LKM
rejects this snapshot version. ksud may stage it while the old LKM is running,
with an explicit warning that the next boot requires the paired LKM.
The early **packet** remains v3 throughout, independently of snapshot version.
SDK C ABI1, HostServices1 and the existing Zygisk/ZN module ABIs are unchanged.

Rebuild LKM, payload, ksud and signed Manager together. A new APK with an old
running LKM is not an acceptance configuration. Keep per-artifact hashes and
the actual Bionic cache hashes alongside local results. QEMU fixtures prove
the tested ABI, ownership and scope behavior; OEM namespace/SELinux policy,
kernel-triggered startup, real Sui UID/socket state and long-running native
modules still require device acceptance.

The standalone YukiZygisk checkout already opens native modules through SYSTEM
with a verified libc caller. It does not expose this new SDK handoff path;
the temporary service protocol is integration-specific and is not copied there.
